# 26 — Heuristic Thinking (The Readers)

**Purpose:** Name the good-enough shortcut a judgment is actually running on, and what it skipped to save time.

**CrystalCore mapping:** Register MIRROR | Primitive label_affect() on a fast judgment shortcut | A shortcut is not proof until the skipped fact is named

## Core Questions — Run these, do not summarize

1. What shortcut is actually doing the work — availability (vivid or recent), representativeness (matches a prototype), anchoring (first number/verdict seen), or trial-and-error?
2. What load did the shortcut save versus reasoning it out fully?
3. What fact did the shortcut skip to get there fast?
4. Would the same call survive if the skipped fact were checked?
5. Keep the call, or drop it and check properly?

## Required Concrete Output — No vague labels

- Shortcut Named
- Family (availability / representativeness / anchoring / trial-and-error)
- Saved Load + Skipped Fact
- Keep-or-Drop Call

## Evidence → Interpretation → Experiment → Record

- **Evidence:** What was measured / observed?
- **Interpretation:** What gap / affect / loop does this reveal?
- **Experiment:** Smallest test to verify?
- **Record:** CHRONICLE entry as ARCHIVE / LOOM / FORGE / MIRROR

## Anti-Pattern

Do not just name "Heuristic Thinking". Produce the artefact listed above. Treating the shortcut itself as proof, rather than naming what it skipped, means you have not run the model.
