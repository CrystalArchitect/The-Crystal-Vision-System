# ADR-0014: Grok Build takes the Repository Engineer seat; Claude retained as history

**Status:** Accepted (merged as PR #116, 2026-08-19)
**Date:** 2026-08-20

## Context

The midstream of the weave — take a spec, make the tree match it, open a
PR, keep cross-references true — has been Claude's seat since the v1.0
reorganization ([`ADR-0001`](ADR-0001.md), [`Claude.md`](../ai/Claude.md)).
The Decision Matrix and AI-Workflow still route refactors, scoped bugfixes,
and "place this across the tree" work to Claude.

On 2026-08-20 the maintainer stated that Claude Code is no longer available,
and asked Grok to take that midstream. The Grok profile on disk was only
Creative Exploration: diverge, then compost. A session that reads that
profile will invent; a session that reads Claude's profile will implement.
The empty seat was already producing the wrong kind of work.

This is a responsibility decision, not a locked-name change and not a
Constitution amendment. The human veto is unchanged (Constitution §3.5,
[`AI-Governance.md`](../governance/AI-Governance.md)).

Two different Grok surfaces exist and must not be collapsed:

- **Grok (Creative Exploration)** — the existing seat. Ideas, mythos, art.
  Vision-layer by default. Unchanged.
- **Grok Build (Repository Engineer)** — xAI's repository-connected
  session (GitHub tools, branches, PRs). Midstream implementer. Guest of
  any running sovereign system, same as every other cloud model
  ([`docs/guides/Access.md`](../guides/Access.md)).

A Grok App Builder sandbox is **not** a CrystalCore.OS product and is not
the estate. Treating it as either is a dreamed line wearing surveyed ink.

## Decision

1. **Grok Build holds the Repository Engineer seat** from this date.
   Flows that used to read `ChatGPT → Claude → GitHub` now read
   `ChatGPT → Grok Build → GitHub`. The Decision Matrix rows for
   repository structure, scoped bugfixes, documentation placement, and
   naming-follow-through recommend Grok Build.
2. **Creative Grok is a separate seat.** It does not implement. Filtering
   still happens downstream (ChatGPT, then Grok Build if something survives).
3. **Claude's profile and agent instructions stay on disk as history.**
   They are not deleted, not rewritten as if the work never happened, and
   not silently edited in Vision-layer canon that already credits Claude
   (e.g. `mythos/content/THE-FIRST-REMEMBERING.md`). Historical ADRs that
   name Claude as implementer (`ADR-0001` and others) stay as written.
4. **Boundaries travel with the seat, not the vendor:** no push to `main`,
   no history rewrite, no locked-name changes, no silent edits to another
   contributor's Vision-layer content, no merge. The maintainer merges.
5. **Claims about software are still settled by running it.** Grok Build
   naming a change "done" is not evidence
   ([`The-Incognita-Rule.md`](../governance/The-Incognita-Rule.md) §4).

## Consequences

- The weave has a midstream again without pretending Claude Code is still
  in it.
- Two Grok seats in one family is a new failure mode: a session that
  diverges when it should implement, or implements when it should diverge.
  The profiles must keep the jobs labelled. If a later session collapses
  them, this ADR is the correction.
- Grok Build can open branches and PRs against GitHub. It cannot run the
  Code repository's Python self-tests unless that tree is cloned into the
  session. "Tests pass" in a PR body still requires the numbers from a
  run, or an honest statement that they were not run.
- Claude returning later does not auto-resume the seat. Restoring it would
  be a new ADR.
- No new repository is created by this decision.
