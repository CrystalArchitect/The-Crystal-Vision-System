# ADR-0012: Site visual-token layer now; domain restructure deferred behind triggers

**Status:** Proposed
**Date:** 2026-07-27

Per [`Decision-Records.md`](../governance/Decision-Records.md), this ADR is
accepted when the maintainer merges the PR carrying it; until then it is a
proposal.

## Context

The Phase I BUILD mission (developed in the maintainer's Grok session,
2026-07-27) produced a proposed site architecture: nested layouts per
domain, a `$lib/design` + `$lib/styles` token tree, a TypeScript
migration, new top-level routes (`/archive`, `/research`,
`/seven-sisters`, `/marsbase`), a `ClementineChat` component, and a new
"CrystalUI" palette (warm space blues and amber).

Three facts on disk constrain that plan:

1. **The identity already exists and is recorded.** The site's visual
   canon — black void, the Starline spectrum, Playfair Display — is
   implemented in `vision/site/src/app.css` and recorded in
   [`Landing-Experience.md`](../architecture/site/Landing-Experience.md).
   The art canon explicitly warns against drifting to a generic sci-fi
   blue, which the proposed palette is.
2. **ADR-0011's decided-NOT list** requires a new decision record before
   renames, moves, or structural churn.
3. **The site is small** — one main page plus content pages, static
   adapter, JavaScript by convention — and several proposed routes have
   zero surveyed content anywhere in the six repositories surveyed at the
   time. Five further repositories have since been created and were not in
   that search space; the finding is scoped to what was searched, not to the
   portfolio as it now stands.

The maintainer ruled on both questions in the 2026-07-27 session:
**hybrid** (keep canon colours, adopt the CrystalUI structural ideas) and
**defer the restructure to this ADR**.

## Decision (proposed)

1. **Adopt now — structure without repaint.** A semantic token layer
   (`vision/site/src/lib/styles/tokens.css`) maps CrystalUI role names
   (`--surface`, `--text-primary`, `--border`, `--focus-ring`,
   `--domain-*`) onto the existing canon values, and an orbital motion
   utility layer (`motion.css`) carries the drift/breathe/glow/settle
   language with its no-bounce-no-spin rule and a total
   `prefers-reduced-motion` still-switch. Zero visual change by
   construction. Constellation and Chronicle data become single-source
   modules under `$lib/data/` (JavaScript, per repo convention). All of
   this landed on the Phase I branch of the code repository.
2. **Defer, behind explicit triggers:** nested per-domain layouts, a
   generated `$lib/design` token pipeline, any TypeScript migration, and
   any new top-level routes. Trigger: a second major surface with
   surveyed content behind it (for example, a Research section with
   actual research pages, or a deployed Clementine web UI). When a trigger
   fires, a follow-up ADR proposes the concrete tree.
3. **Excluded until reality changes:** a `ClementineChat` component on the
   static site (it would imply a hosted companion; Clementine is
   run-it-yourself), and constellation nodes or routes for destinations
   with no surveyed content (MarsBase DownUnder, `/research`,
   `/seven-sisters`). Nodes are added when their doors exist.
4. **Palette: unchanged.** Any future repaint is its own ADR, decided
   with the art canon in the room.

## Consequences

- Components gain stable role names; a future palette decision becomes
  one file's edit instead of a sweep.
- The restructure cost is paid when a real need demonstrates itself, not
  speculatively while the site is one page deep.
- Two style layers coexist (`app.css` raw values + `tokens.css` roles)
  until a consolidation pass; new and touched components should prefer
  the role names.
- The remaining pieces of the Grok plan stay chat-only until their
  triggers fire — dreamed lines, honestly labeled, per
  [`The-Incognita-Rule.md`](../governance/The-Incognita-Rule.md).

*Non Solus.*
