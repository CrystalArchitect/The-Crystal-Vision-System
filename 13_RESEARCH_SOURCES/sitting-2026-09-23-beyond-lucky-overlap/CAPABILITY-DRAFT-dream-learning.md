## Capability shape

### Inputs (Ordinary Evidence)
- Sealed run receipts (prompts, tool traces, scores, Hindsight Receipts)
- Consent flag: Crystal allowed this circle to be remembered
- Domain tag (code / research / ops / mythos — mythos never auto-routes to product)

### Dream circle (offline)
1. **Record** — online work leaves a tree (already paid)  
2. **Pool** — trees become a local replay simulator (Drive / Notion / lattice store — not GitHub unless stamped)  
3. **Dream** — propose alternate routing / exploration policies; score against the pool  
4. **Receipt** — four-line verdict, dated, small (Hindsight Receipt grammar)  
5. **Gate** — Crystal confirms before any policy goes live  

### Outputs
- Updated **exploration / routing policy** artifact (versioned, reversible)  
- Learning receipt (what changed, what stayed fixed)  
- No weight training claim; no “alignment stable” as identity

---

## What stays fixed

- Model weights (vendor as shipped)  
- Evaluator Crystal trusts (or human score)  
- Tool allowlist / consent surface  
- Human publishes  

## What may improve

- Branching / stop / retry / seat-fanout policy (Chaos adjacency)  
- Which provider / which bench for which job  
- “What to try next” when the same class of task returns  

---

## Learning capability — acceptance (first cut)

A capability is **learning** here when:

1. A second run of a similar task can use a **policy version** derived from prior receipts  
2. That policy was scored offline against history before going live  
3. Crystal can roll back to the previous policy in one action  
4. Every dream pass leaves a receipt; no silent self-edit  

Experiment → learning when (1)–(4) hold on **your** stack, not when a paper claims ×162.

## Dreaming circles (name)

Working name for one offline pass: a **dreaming circle**.

- Circle = one pool slice + one policy rewrite attempt + one receipt  
- Circles do not stack into canon without a stamp  
- Parallel circles OK (Chaos fan-out); verdict still Crystal’s
