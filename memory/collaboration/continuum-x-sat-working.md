The important distinction
I would make memory/CORE.md extremely small.
An AI shouldn’t have to ingest 100,000 lines to understand the project.
The hierarchy becomes:
CORE → INDEX → relevant memory → authoritative document → archive
So a new AI could be given:
Read memory/CORE.md.
Then read memory/INDEX.md.
Follow only the branches relevant to this task.
Treat the repository as the source of truth.
Do not infer missing facts.
That is much more portable across ChatGPT, Claude, Gemini, Grok, DeepSeek, local models, future agents, and ordinary context windows.
Your existing Constitution already establishes an important version of this hierarchy: disk canon outranks chat memory, and the repository is the primary canon.
And your existing AI workflow already says that handoffs should happen through artifacts rather than conversational context.
So we’re not inventing a foreign architecture. We’re making the architecture you already built usable as memory.
I would also preserve the four memory concepts
Your existing MEMORY.md has:
                              *Working
                              * Episodic
                              *Semantic
                              * Reflective
That’s useful for an actual companion/runtime, but it’s not quite the right top-level structure for repository memory.
I’d separate:
AI/project memory
 → enduring knowledge, decisions, state, relationships between concepts
from
runtime companion memory
 → conversations, episodes, reflections, user-editable memories
That prevents the repository from becoming confused about whether MEMORY.md describes the software’s memory implementation or the project’s shared memory.
And there’s a really important rule I’d add
Every memory item should carry a tiny amount of provenance:
status: canonical | verified | proposed | hypothesis | historical
source: <file/path>
updated: YYYY-MM-DD
confidence: high | medium | low
That directly reinforces the governance rule you already have: an AI agreeing with something isn’t evidence, and substantial material must distinguish Built from Vision.
It also protects against exactly the failure you’re trying to solve: one AI reads an old context, confidently states it as fact, another AI absorbs that statement, and suddenly the error has become “memory.”
